# دليل تثبيت VAR HR USB Device Connector على Windows

هذا الدليل مكتوب خطوة بخطوة لشخص لا يحتاج إلى خبرة تقنية.

النتيجة التي نريدها في النهاية:

1. جهاز البصمة ZKTeco LX15 يظل متصلًا بكمبيوتر الشركة عن طريق USB.
2. برنامج VAR HR يعمل في الخلفية تلقائيًا.
3. كل سجلات الحضور والانصراف تنتقل إلى الموقع بدون تصدير ملفات أو رفعها يدويًا.
4. عند إعادة تشغيل الكمبيوتر، يعود البرنامج للعمل تلقائيًا.

---

## أولًا: الأشياء المطلوبة قبل أن نبدأ

### من جهاز الشركة

- كمبيوتر يعمل بنظام Windows 10 أو Windows 11.
- صلاحية Administrator على الكمبيوتر، أي القدرة على تثبيت البرامج.
- كابل USB يعمل لتوصيل LX15 بالكمبيوتر.
- اتصال إنترنت مستمر.
- جهاز LX15 يعمل ويمكن تسجيل بصمة تجريبية عليه.

### من موقع VAR HR

- حساب مالك الشركة أو حساب لديه صلاحية إدارة الأجهزة.
- أرقام المستخدمين الموجودة داخل جهاز البصمة.
- معرفة الموظف الذي ينتمي إليه كل رقم مستخدم.

### مهم جدًا

لا تحتاج إلى تثبيت Node.js أو Python أو قاعدة بيانات أو Docker.

الموصل الذي أعددناه يعمل باستخدام Windows PowerShell الموجود أصلًا في Windows.

## ثانيًا: ما الذي يجب تنزيله من الإنترنت؟

يوجد شيئان مختلفان:

### 1. برنامج الموصل من VAR HR

ملفات الموصل موجودة مع هذا الدليل داخل نفس المجلد:

```text
scripts/var-hr-device-connector/
```

إذا تم إرسال المجلد لك مضغوطًا، سيكون اسم الملف غالبًا:

```text
VAR-HR-USB-Connector-Windows.zip
```

فك ضغطه في هذا المكان على كمبيوتر الشركة:

```text
C:\VAR-HR\USB-Connector
```

بعد فك الضغط يجب أن ترى الملفات التالية:

```text
C:\VAR-HR\USB-Connector\config.example.json
C:\VAR-HR\USB-Connector\read-zkteco-usb.ps1
C:\VAR-HR\USB-Connector\run.ps1
C:\VAR-HR\USB-Connector\install.ps1
```

### 2. SDK الخاص بشركة ZKTeco

الموصل يحتاج إلى مكوّن Windows من ZKTeco اسمه غالبًا:

```text
ZKEMKeeper
```

ويكون الملف أو المكوّن الأساسي له غالبًا:

```text
zkemkeeper.dll
```

رابط صفحة SDK الرسمية لشركة ZKTeco:

https://www.zkteco.com/en/SDK

افتح الرابط من كمبيوتر Windows، ثم ابحث داخل صفحة التنزيلات عن SDK الخاص بأجهزة
Standalone Attendance أو عن حزمة تحتوي على ZKEMKeeper.

### لا تنزل أي DLL من مواقع عشوائية

لا تبحث عن `zkemkeeper.dll` وتحمله من موقع غير معروف؛ لأن ملفات DLL المعدلة
قد تحتوي على فيروسات أو لا تكون متوافقة مع جهاز LX15.

إذا لم تجد ZKEMKeeper في صفحة التنزيل الرسمية، تواصل مع دعم ZKTeco واطلب منهم
بالاسم:

```text
Windows Standalone SDK / ZKEMKeeper compatible with ZKTeco LX15
```

اذكر لهم أيضًا إصدار Firmware الموجود في جهاز LX15، لأن بعض الإصدارات تحتاج
نسخة SDK مختلفة.

صفحة SDK الرسمية الحالية قد تعرض حزمًا لأجهزة أخرى مثل قارئات البصمة
ZKFinger. لا تنزل ZKFinger إلا إذا قالت لك ZKTeco صراحة إنه متوافق مع LX15؛
المطلوب هنا هو SDK الخاص بجهاز الحضور Standalone وليس قارئ بصمة USB عادي.

## ثالثًا: إنشاء الجهاز داخل VAR HR

نفذ هذه الخطوات من متصفح الإنترنت:

1. افتح موقع VAR HR وسجل الدخول.
2. افتح صفحة **الأجهزة** أو **Biometric Devices**.
3. اضغط **إضافة جهاز**.
4. املأ البيانات كالتالي:

   - **اسم الجهاز:** مثلًا `LX15 - فرع القاهرة`.
   - **الشركة المصنعة:** `ZKTeco`.
   - **الموديل:** `LX15`.
   - **نوع الاتصال:** `USB connector`.
   - **Adapter:** اتركه فارغًا إذا ظهر الحقل؛ سيستخدم النظام تلقائيًا:
     `zkteco-usb`.
   - **الفرع:** اختر الفرع الصحيح.

5. اضغط حفظ.
6. سيظهر لك مفتاح تسجيل طويل.
7. انسخ المفتاح إلى ملف مؤقت آمن مثل Notepad.

### تنبيه بخصوص مفتاح التسجيل

- المفتاح يظهر مرة واحدة فقط.
- لا ترسله في WhatsApp أو بريد غير آمن.
- لا تضعه في صورة شاشة أو مستند عام.
- إذا ضاع المفتاح، احذف الجهاز من VAR HR وأنشئ جهازًا جديدًا للحصول على مفتاح
  جديد.

في نفس صفحة الجهاز ستجد **Device ID**. انسخه أيضًا؛ سيكون شكل الرقم مثل:

```text
xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx
```

## رابعًا: توصيل جهاز LX15

1. شغّل جهاز LX15.
2. وصّل كابل USB بين LX15 وكمبيوتر الشركة.
3. انتظر دقيقة واحدة.
4. إذا ظهر Windows برسالة تثبيت Driver، اتركه حتى ينتهي.
5. لا تفصل الكابل أثناء أول اختبار.

إذا لم يتعرف Windows على الجهاز:

- جرّب منفذ USB آخر.
- جرّب كابلًا آخر.
- لا تستخدم USB Hub في أول تجربة.
- أعد تشغيل جهاز LX15 والكمبيوتر.
- لا تنتقل إلى الخطوة التالية قبل التأكد من أن الكابل سليم.

## خامسًا: تثبيت SDK الخاص بـ ZKTeco

### إذا كان التنزيل ملف ZIP أو RAR

1. اضغط بزر الماوس الأيمن على الملف الذي نزلته.
2. اختر **Extract All** إذا كان ZIP.
3. إذا كان RAR، استخدم برنامج فك ضغط موثوق مثل 7-Zip.
4. افتح المجلد الناتج.
5. ابحث عن ملف تثبيت اسمه قريب من:

   ```text
   Setup.exe
   Install.exe
   ZKEMKeeper Setup.exe
   ```

6. اضغط بزر الماوس الأيمن على ملف التثبيت.
7. اختر **Run as administrator**.
8. اضغط Next حتى نهاية التثبيت.
9. إذا طلب البرنامج إعادة تشغيل Windows، وافق على إعادة التشغيل.

### إذا كانت الحزمة لا تحتوي على ملف Setup

لا تنسخ DLL عشوائيًا إلى مجلدات Windows بنفسك.

افتح الملف المرفق مع SDK، وغالبًا يكون اسمه:

```text
README
Installation Guide
User Manual
```

واتبع تعليمات ZKTeco لتسجيل مكوّن COM.

بعض نسخ SDK تكون 32-bit حتى على Windows 64-bit. هذا طبيعي. لا تحاول استبدال
نسخة 32-bit بنسخة 64-bit إلا إذا كانت تعليمات ZKTeco تطلب ذلك.

## سادسًا: تجهيز ملفات الموصل

بعد تنزيل وفك ضغط ملفات VAR HR:

1. افتح المجلد:

   ```text
   C:\VAR-HR\USB-Connector
   ```

2. اضغط بزر الماوس الأيمن على الملف:

   ```text
   config.example.json
   ```

3. اختر **Copy**.
4. اضغط بزر الماوس الأيمن في نفس المجلد واختر **Paste**.
5. أعد تسمية النسخة الجديدة إلى:

   ```text
   config.json
   ```

6. افتح `config.json` باستخدام Notepad.

سيكون محتواه شبيهًا بهذا:

```json
{
  "apiBaseUrl": "https://YOUR-VAR-HR-DOMAIN",
  "deviceId": "DEVICE_UUID",
  "registrationKey": "ONE_TIME_DEVICE_REGISTRATION_KEY",
  "machineNumber": 1,
  "pollIntervalSeconds": 30
}
```

غيّر القيم الثلاث التالية فقط:

### apiBaseUrl

اكتب رابط موقع VAR HR الأساسي بدون `/api` في النهاية.

مثال:

```json
"apiBaseUrl": "https://hr.example.com"
```

لا تكتب:

```text
https://hr.example.com/api
https://hr.example.com/
```

### deviceId

ضع قيمة **Device ID** التي نسختها من صفحة الجهاز في VAR HR.

### registrationKey

ضع مفتاح التسجيل الذي ظهر بعد إنشاء الجهاز.

بعد التعديل، يجب أن يصبح الملف مثل هذا المثال:

```json
{
  "apiBaseUrl": "https://hr.example.com",
  "deviceId": "11111111-2222-3333-4444-555555555555",
  "registrationKey": "ضع-المفتاح-الذي-ظهر-في-VAR-HR-هنا",
  "machineNumber": 1,
  "pollIntervalSeconds": 30
}
```

احفظ الملف من Notepad باستخدام:

```text
File > Save
```

### مهم جدًا عند الحفظ

تأكد أن اسم الملف هو:

```text
config.json
```

وليس:

```text
config.json.txt
```

للتأكد من ذلك في File Explorer:

1. افتح View.
2. اختر Show.
3. فعّل **File name extensions**.
4. إذا ظهر `config.json.txt`، أعد تسميته إلى `config.json`.

## سابعًا: فتح PowerShell في مجلد الموصل

1. افتح المجلد:

   ```text
   C:\VAR-HR\USB-Connector
   ```

2. اضغط بزر الماوس الأيمن في مكان فارغ داخل المجلد.
3. اختر **Open in Terminal** أو **Open PowerShell window here**.

إذا لم يظهر الخيار:

1. اضغط زر Start.
2. اكتب `PowerShell`.
3. افتح **Windows PowerShell**.
4. اكتب الأمر التالي:

   ```powershell
   cd C:\VAR-HR\USB-Connector
   ```

## ثامنًا: اختبار SDK والجهاز قبل تشغيل الخدمة

داخل PowerShell، نفذ الأمر التالي:

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\read-zkteco-usb.ps1 -MachineNumber 1
```

إذا كان كل شيء سليمًا، سيظهر نص طويل يحتوي على سجلات بصيغة JSON، مثل:

```json
{"deviceEmployeeId":"12","occurredAt":"2026-09-01T06:30:00.0000000Z","direction":"in", ...}
```

هذا يعني أن Windows استطاع:

- تشغيل ZKEMKeeper.
- رؤية جهاز LX15.
- قراءة سجلات الحضور.

### إذا ظهر خطأ عن ZKEMKeeper

مثل:

```text
ZKTeco SDK is not installed or zkemkeeper.dll is not registered.
```

فهذا يعني أن SDK لم يتم تثبيته أو لم يتم تسجيله. أعد خطوة تثبيت SDK، ولا
تنسخ DLL عشوائيًا إلى مجلد Windows.

### إذا ظهر خطأ عن USB

مثل:

```text
Could not connect to a ZKTeco device over USB.
```

نفذ الآتي بالترتيب:

1. تأكد أن LX15 يعمل.
2. افصل كابل USB وأعد توصيله.
3. جرّب منفذ USB آخر.
4. أعد تشغيل LX15.
5. أعد تشغيل PowerShell كمسؤول.
6. جرّب مرة أخرى.

### إذا لم تظهر سجلات

قد يكون الجهاز متصلًا لكن لا توجد بصمات جديدة. سجّل بصمة تجريبية على LX15،
ثم شغّل أمر القراءة مرة أخرى.

## تاسعًا: تثبيت الموصل ليعمل تلقائيًا

بعد نجاح اختبار القراءة، أغلق نافذة PowerShell القديمة وافتح PowerShell جديدًا
بصلاحية Administrator:

1. اضغط Start.
2. اكتب `PowerShell`.
3. اضغط بزر الماوس الأيمن على Windows PowerShell.
4. اختر **Run as administrator**.
5. وافق على رسالة Windows.
6. نفذ:

   ```powershell
   cd C:\VAR-HR\USB-Connector
   Set-ExecutionPolicy -Scope Process Bypass
   .\install.ps1
   ```

إذا نجح التثبيت ستظهر رسالة قريبة من:

```text
Installed and started VAR HR USB Device Connector.
```

من هذه اللحظة:

- سيعمل الموصل في الخلفية.
- سيقرأ السجلات كل 30 ثانية.
- سيرسل السجلات للموقع.
- سيعمل مرة أخرى تلقائيًا بعد إعادة تشغيل الكمبيوتر.

لا تغلق Windows PowerShell لأن الخدمة تعمل من خلال Windows Task Scheduler وليس
من خلال نافذة PowerShell نفسها.

## عاشرًا: التأكد من أن الخدمة تعمل

1. اضغط Start.
2. اكتب:

   ```text
   Task Scheduler
   ```

3. افتح البرنامج.
4. من القائمة اليسرى اختر **Task Scheduler Library**.
5. ابحث عن:

   ```text
   VAR HR USB Device Connector
   ```

6. يجب أن تكون الحالة:

   ```text
   Running
   ```

إذا كانت الحالة Ready بدل Running، اضغط بزر الماوس الأيمن على المهمة واختر
**Run**.

## الحادي عشر: ربط أرقام جهاز البصمة بالموظفين

إنشاء الجهاز وتشغيل الموصل لا يكفي وحده. يجب ربط رقم كل مستخدم بالموظف الصحيح:

1. افتح صفحة الأجهزة في VAR HR.
2. افتح جهاز LX15.
3. افتح قسم **Employee mappings**.
4. أضف الرقم الموجود في LX15.
5. اختر الموظف المطابق لهذا الرقم.
6. احفظ.

مثال:

| رقم المستخدم في LX15 | الموظف |
|---|---|
| 12 | أحمد |
| 13 | محمد |
| 14 | سارة |

إذا وصل سجل لرقم غير مربوط، لن ينسبه النظام إلى موظف عشوائي. سيظهر كسجل غير
مربوط حتى يتم تصحيح الربط.

## الثاني عشر: اختبار كامل من البداية للنهاية

بعد ربط الموظفين:

1. سجل بصمة دخول لموظف تجريبي على LX15.
2. انتظر حتى 30 ثانية.
3. افتح صفحة الحضور في VAR HR.
4. تأكد من ظهور وقت الدخول.
5. سجل بصمة خروج.
6. انتظر حتى 30 ثانية.
7. تأكد من ظهور وقت الخروج وحساب ساعات العمل.

إذا ضغط الموظف نفس البصمة أكثر من مرة، لن يؤدي ذلك إلى إنشاء سجل مكرر لنفس
الحدث؛ الموصل يستخدم مفتاحًا يمنع التكرار.

## الثالث عشر: إذا تغير رابط موقع VAR HR أو مفتاح التسجيل

افتح:

```text
C:\VAR-HR\USB-Connector\config.json
```

وعدّل `apiBaseUrl` أو `registrationKey`، ثم أعد تشغيل مهمة Windows:

```powershell
Stop-ScheduledTask -TaskName "VAR HR USB Device Connector"
Start-ScheduledTask -TaskName "VAR HR USB Device Connector"
```

لا تحتاج إلى إنشاء جهاز جديد إلا إذا ضاع مفتاح التسجيل أو تم إلغاؤه.

## الرابع عشر: أشهر الأخطاء وحلها

### الخطأ: `config.json was not found`

السبب: لم يتم إنشاء نسخة من `config.example.json`.

الحل:

```powershell
Copy-Item .\config.example.json .\config.json
```

ثم افتح `config.json` واكتب البيانات الصحيحة.

### الخطأ: `apiBaseUrl, deviceId, and registrationKey are required`

السبب: إحدى القيم الثلاث فارغة أو مكتوبة باسم خاطئ.

افتح الملف وتأكد أن الأسماء مكتوبة بالضبط:

```text
apiBaseUrl
deviceId
registrationKey
```

### الخطأ: `401 A valid device registration key is required`

السبب غالبًا واحد من الآتي:

- مفتاح التسجيل غير صحيح.
- تم نسخ مسافة في أول المفتاح أو آخره.
- تم استخدام مفتاح جهاز آخر.
- تم حذف الجهاز وإنشاء جهاز جديد، فأصبح المفتاح القديم غير صالح.

الحل: انسخ المفتاح مرة أخرى من VAR HR، وإذا لم يعد ظاهرًا أنشئ جهازًا جديدًا.

### الخطأ: `404 USB connector device not found`

السبب غالبًا:

- Device ID غير صحيح.
- الجهاز غير مضبوط كـ USB connector.
- قيمة Adapter ليست `zkteco-usb`.

افتح الجهاز في VAR HR وتأكد من البيانات.

### الموصل يعمل لكن الحضور لا يظهر

تحقق من الآتي بالترتيب:

1. هل ظهرت سجلات JSON عند اختبار `read-zkteco-usb.ps1`؟
2. هل `apiBaseUrl` صحيح؟
3. هل الكمبيوتر متصل بالإنترنت؟
4. هل Device ID صحيح؟
5. هل registrationKey صحيح؟
6. هل رقم المستخدم مربوط بالموظف؟
7. هل وقت وتاريخ LX15 صحيحان؟

### السجل يظهر غير مربوط

السبب أن رقم المستخدم داخل LX15 لم يتم ربطه بموظف في VAR HR.

لا تغيّر الرقم داخل السجل يدويًا؛ أضف mapping صحيحًا من صفحة الجهاز.

### بعد إعادة تشغيل الكمبيوتر لا يعمل الموصل

افتح Task Scheduler وتأكد من وجود:

```text
VAR HR USB Device Connector
```

إذا لم توجد المهمة، شغّل `install.ps1` مرة أخرى كمسؤول.

إذا كانت المهمة موجودة لكنها تفشل، افتح خصائصها وتأكد من أن:

- المسار يشير إلى `C:\VAR-HR\USB-Connector\run.ps1`.
- ملفات الموصل لم يتم نقلها بعد تثبيت المهمة.
- SDK مثبت على نفس الكمبيوتر.

### الموصل يعمل عند الاختبار اليدوي فقط

قد تكون نسخة SDK مرتبطة بمستخدم Windows الحالي وليس بكل مستخدمي الجهاز.

في هذه الحالة:

1. افتح خصائص مهمة Task Scheduler.
2. اذهب إلى تبويب **General**.
3. جرّب تشغيل المهمة بحساب Windows الذي تم تثبيت SDK عليه.
4. احفظ وشغّل المهمة مرة أخرى.

---

## الخامس عشر: حماية ملف الإعداد

ملف `config.json` يحتوي على مفتاح يسمح بإرسال سجلات إلى جهاز محدد، لذلك:

- لا ترسله لأي شخص.
- لا ترفعه إلى Google Drive عام.
- لا تضعه داخل GitHub.
- لا تضعه في مجلد مشترك لكل الموظفين.
- احتفظ بنسخة احتياطية آمنة فقط إذا احتجت إليها.

ملف `config.example.json` لا يحتوي على مفتاح حقيقي ويمكن مشاركته.

## السادس عشر: تركيب أكثر من جهاز

لكل جهاز بصمة:

1. أنشئ جهازًا مستقلًا داخل VAR HR.
2. احصل على Device ID ومفتاح تسجيل مستقل.
3. استخدم مجلدًا مستقلًا، مثل:

   ```text
   C:\VAR-HR\USB-Connector-LX15-Cairo
   C:\VAR-HR\USB-Connector-LX15-Giza
   ```

4. ضع `config.json` مختلفًا لكل جهاز.
5. عند التثبيت استخدم اسم مهمة مختلفًا:

   ```powershell
   .\install.ps1 -TaskName "VAR HR USB Connector - Cairo"
   ```

لا تستخدم نفس `config.json` لجهازين مختلفين.

## ملخص سريع جدًا

إذا كنت تريد قائمة مختصرة بعد قراءة الشرح:

1. نزّل SDK الرسمي المتوافق مع LX15 من ZKTeco.
2. ثبّت SDK كمسؤول.
3. فك ملفات الموصل في:

   ```text
   C:\VAR-HR\USB-Connector
   ```

4. أضف جهازًا في VAR HR بنوع:

   ```text
   USB connector
   ```

5. انسخ `config.example.json` إلى `config.json`.
6. ضع رابط الموقع وDevice ID ومفتاح التسجيل.
7. وصّل LX15 بالـ USB.
8. اختبر:

   ```powershell
   .\read-zkteco-usb.ps1 -MachineNumber 1
   ```

9. ثبّت التشغيل التلقائي:

   ```powershell
   .\install.ps1
   ```

10. اربط أرقام المستخدمين بالموظفين.
11. سجّل بصمة تجريبية وتأكد من ظهورها في VAR HR.
