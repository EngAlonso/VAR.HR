We need to correct an important account-model/UI confusion in the Company Owner account-management system.

There are TWO different account-creation concepts in this product. Do NOT merge them.

TYPE 1 — Manually created management/staff accounts

These are accounts created manually by a Company Owner for people who will help manage the company.

Examples:

- HR
- Payroll administrator
- Attendance/bio administrator
- Manager
- Accountant
- Any other staff member who receives selected permissions

The Company Owner manually creates this account and decides exactly what it can access.

Required fields

The Create Account form for this type MUST contain separate fields for:

1. Employee Name

This is the person's real/display name.

Examples:

- أحمد محمد
- Mohamed Ahmed
- أحمد Ahmed
- أي اسم بشري مناسب

Rules:

- Arabic allowed.
- English allowed.
- Mixed Arabic/English allowed.
- Spaces allowed.
- Do NOT apply the technical username regex to this field.
- This is a display/human name, not the login identifier.

Arabic label:
اسم الموظف

English:
Employee Name

2. Phone Number

The phone number is the account's login username / identifier.

The employee should log in using this phone number.

Therefore:

Username = Phone Number

Do NOT ask the Company Owner to manually invent a username such as:
"ahmed_admin"
"hr01"
etc.

The username/login identifier should come from the phone number field.

Keep the existing uniqueness requirement for phone/login identifiers.

Use the appropriate phone-number validation already used by the project. Do not allow arbitrary text to be used as the login identifier.

Arabic:
رقم الهاتف

3. Password

The Company Owner chooses the initial password.

Current required rule:

- Minimum 6 characters.
- No requirement for uppercase.
- No requirement for lowercase.
- No requirement for numbers.
- No requirement for special characters.

The employee can later change their password normally, but changing their password requires the current/old password.

4. Job Title

The Company Owner should be able to enter/select the employee's job title.

Arabic:
المسمى الوظيفي

5. Permissions

The Company Owner selects exactly which permissions this account receives.

Keep the existing permission selector and the existing:

- تحديد الكل
- إلغاء تحديد الكل

functionality.

Do not change the underlying permission keys or authorization system.

Account Management behavior

The Company Owner should have a section such as:

حسابات الموظفين

But in this context, this section is specifically for the manually created management/staff accounts described above.

It should show the accounts created by the Owner for people such as HR, managers, payroll administrators, etc.

For each account, the Owner should be able to see:

- Employee Name
- Phone Number
- Job Title
- Assigned Permissions
- Account status

The Owner should be able to view the account details and manage its permissions.

---

Password behavior

There are TWO different password operations.

Employee changes their own password

If the employee wants to change their password normally:

They MUST provide the old/current password.

This is the normal password-change flow.

Company Owner resets the employee password

The Company Owner can reset the password of a management/staff account they created without knowing the employee's current password.

This is an administrative password reset.

The Owner should NOT need the old password for this operation.

---

Critical security rule

A Company Owner must ONLY be able to manage accounts belonging to their own company/tenant.

Do NOT allow:

- Owner A to see Owner B's accounts.
- Owner A to reset Owner B's password.
- Owner A to modify Owner B's account.
- Owner A to change another company's staff permissions.

Preserve the existing tenant isolation and authorization rules.

Also:

One Company Owner must NOT be able to change or reset another Company Owner's password.

The Owner's own account is a different security level and must not be included in the normal company-staff management/reset flow.

Do NOT weaken owner/platform authorization to implement this.
