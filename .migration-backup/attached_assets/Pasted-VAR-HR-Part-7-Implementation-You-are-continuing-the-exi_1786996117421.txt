5. Leave & Permission Management

Implement a complete leave/permission workflow.

Leave types

Support multiple leave types.

Each company should be able to define leave types and their rules.

Employee balances

Maintain leave balances per employee and leave type.

Support:

- Available balance
- Used balance
- Remaining balance
- Balance adjustments where authorized

Requests

Employees must be able to submit:

- Leave requests
- Permission requests

A request should contain the appropriate date/time, duration, type, reason, and status.

Approval

Managers/authorized HR users must be able to:

- Review requests
- Approve
- Reject
- Provide a rejection reason

Automatic balance handling

When an approved leave consumes balance:

- Deduct the appropriate amount.
- Prevent invalid/negative consumption unless explicitly allowed by company rules.
- Restore the balance if an approved leave is cancelled/reversed according to the business rules.

History

Maintain a complete request history.

Employees can see their own requests.

Managers can see requests belonging to employees within their allowed scope.

Owners/authorized HR users can see company-wide requests.

11. Role-Based Access Control

Maintain strict tenant isolation and role boundaries.

Employee

Can access:

- Own profile
- Own attendance
- Own clock-in/out
- Own leave balances
- Own leave/permission requests
- Own salary/payroll information where allowed

Cannot access other employees' confidential information.

Manager

Can access employees within their authorized management scope.

Can:

- Review attendance
- Review leave requests
- Approve/reject requests
- Review team information
- Access permitted reports

Must NOT automatically gain access to company-wide payroll or unrelated departments.

Owner

Can access the company-wide HR functionality:

- Employees
- Attendance
- Leaves
- Payroll
- Reports
- Devices
- Rules
- Schedules
- Holidays
- Company settings

Developer

Keep Developer separate from Owner.

Developer permissions should focus on technical functionality such as:

- Integrations
- API configuration
- Biometric devices
- Logs
- Diagnostics
- System configuration

Developer must NOT automatically receive employee salary/payroll visibility merely because they have technical privileges.

Implement explicit permissions where necessary.
