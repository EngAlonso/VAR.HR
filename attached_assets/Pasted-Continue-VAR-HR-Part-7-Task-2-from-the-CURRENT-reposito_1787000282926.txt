## 3. Employee synchronization

Implement the synchronization flow between VAR HR and the provider abstraction.

The flow should support the existing employee/device model:

VAR HR employee
→ selected biometric device/provider
→ provider synchronization
→ result
→ sync history

Respect company/tenant isolation and existing authorization.

Do not allow one company's employees to be synchronized to another company's device.

## 4. Attendance synchronization

Implement provider attendance/event synchronization through the existing abstraction.

The flow should:

1. Obtain biometric attendance events from the provider.
2. Validate/map the employee/device identity.
3. Associate the event with the correct company.
4. Persist the attendance event using the existing attendance model.
5. Avoid creating duplicate attendance records when the same provider event is synchronized again.
6. Record the synchronization result.

Do not rewrite the existing attendance calculation/rules engine.

This task is only about getting biometric events safely into the existing attendance system.

## 5. Sync history

Complete the synchronization history behavior using the Task 1 schema.

Record appropriate information such as:

- provider/device
- providerKey
- operation
- start/end status where supported
- success/failure
- error information
- synchronized record counts/results

Use the existing `DeviceSyncHistory` model.

Do not create another sync-history table.

Do not expose credentials or sensitive device configuration.

## 6. Retry/idempotency

Synchronization must be safe to run more than once.

For the same provider attendance event:

- the first synchronization should create the attendance record;
- repeating the same event should not create a duplicate;
- the sync history should still accurately record the subsequent synchronization attempt/result.

Use the existing database/provider identifiers where available.

Do not introduce unnecessary infrastructure.

## 7. Authorization and tenant isolation

Keep the Task 1 authorization model.

Employee:
- no access to biometric device administration or synchronization controls.

Manager:
- no company-wide biometric administration unless existing permissions explicitly allow it.

Owner/authorized HR:
- may manage/synchronize devices within their company according to existing permissions.

Developer:
- technical/integration access only according to existing permissions.
- Do not automatically grant payroll or confidential employee access.

Every provider/device/employee/event query must remain company-scoped.

Cross-company synchronization must be rejected.
