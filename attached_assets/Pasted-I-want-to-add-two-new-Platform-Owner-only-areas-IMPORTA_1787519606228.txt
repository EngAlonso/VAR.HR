==================================================
1. Platform Database Administration
==================================================

Add a dedicated Platform Owner-only area called:

Arabic:
إدارة قاعدة البيانات

English:
Database Administration

This area is for emergency/support operations and should allow the Platform Owner to manage the application's database data.

The Platform Owner should be able to:

### View database data

Browse the application's database tables/entities and inspect their records.

Show useful information such as:
- Table/entity name
- Record count
- Records/data
- IDs
- Created/updated dates where available

### Export data

Allow the Platform Owner to export database data as Excel (.xlsx).

Requirements:
- Export selected table/entity.
- Export filtered/selected records if supported.
- Keep Arabic/English column labels where appropriate.
- Do not expose password hashes or sensitive authentication secrets in normal exports.
- Do not export session tokens, cookies, API keys, or other secrets.

### Manual editing

Allow the Platform Owner to manually edit database records for emergency/support purposes.

Support:
- Edit individual record
- Update individual fields
- Save changes
- Delete individual record

Use the existing API/database architecture rather than giving the browser direct database access.

### Delete / Clear operations

Provide controlled emergency operations for:

1. Delete one record.
2. Delete selected records.
3. Clear selected data/entity/table.
4. Clear a specific subset of data using filters where safely supported.
5. Clear an entire table/entity only when explicitly confirmed.

DO NOT provide a single accidental "Delete Database" button.

For destructive operations:

- Require a strong confirmation dialog.
- Clearly explain exactly what will be deleted.
- Require the Platform Owner to type a confirmation phrase for dangerous operations.
- For example:
  "DELETE EMPLOYEES"
  or the equivalent Arabic confirmation phrase.
- Show affected record count before deletion.
- Prevent accidental double submission.
- Show success/failure result.

### Safety

This is an emergency administration tool, so preserve database integrity.

Do NOT allow arbitrary SQL execution from the browser.

Do NOT allow the user to execute DROP DATABASE, DROP TABLE, arbitrary SQL, or destructive SQL directly.

Use controlled server-side operations with explicit allowlists for editable/deletable entities and fields.

Respect foreign keys and existing database relationships.

If deleting a record would violate a relationship, show a clear error instead of corrupting or bypassing the database.

### Audit logging

Every database administration action MUST be logged.

Log:
- Platform Owner ID
- Action
- Entity/table
- Record ID(s) when applicable
- Fields changed
- Before/after values where safe
- Number of records affected
- Timestamp
- Success/failure

Never put passwords, password hashes, session tokens, or other secrets into the audit log.
