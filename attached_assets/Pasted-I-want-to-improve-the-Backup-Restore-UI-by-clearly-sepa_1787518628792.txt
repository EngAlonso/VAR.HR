I want to improve the Backup & Restore UI by clearly separating the two different operations for both Platform Owner and Company Owner.

There must be a very clear visual and functional separation between:

1. Download / Export Backup
   - This represents a backup generated by the VAR HR system and downloaded to the user's device.
   - Show it in a dedicated section/card such as:
     "نسخ احتياطية محفوظة"
     / "Downloaded Backups"
   - Provide the existing Download action.
   - Do not confuse this section with files selected for restoration.

2. Restore From Device
   - This represents a backup file that the user selects FROM their device to restore into VAR HR.
   - Show it in a completely separate section/card such as:
     "استعادة من الجهاز"
     / "Restore from Device"
   - Provide a file picker/upload control.
   - Clearly indicate that selecting a file here does NOT create or download a backup; it is an input for the Restore operation.

### UI requirement

Make the separation visually obvious.

For example:

[ Backup / Download ]
- Create Backup
- Available backups
- Download

----------------------------

[ Restore from Device ]
- Select backup file
- Show selected filename
- Validate backup
- Restore

Do not mix downloaded backup files and files selected for restore in the same list.

### Apply this to both:

- Platform Owner
- Company Owner

But preserve their existing authorization and tenant isolation.

Company Owner:
- Only sees/restores backups belonging to their own company.
- Must not access another company's backups.

Platform Owner:
- Keeps the existing platform-level backup/restore permissions and scope.

Do NOT redesign or replace the existing backup/restore backend unless the current implementation requires a small change.

First inspect the existing Backup & Restore implementation and identify whether this is only a UI/UX separation or whether the backend currently mixes the two concepts.

Preserve:
- Existing backup format
- Existing validation
- Existing integrity checks
- Existing tenant isolation
- Existing restore authorization
- Existing database behavior

The goal is primarily to make it impossible for the user to confuse:
