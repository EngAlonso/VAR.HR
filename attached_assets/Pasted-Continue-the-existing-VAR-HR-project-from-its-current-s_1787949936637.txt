- The generated password is NOT temporary.
- There must be no "temporary password" concept.
- The employee does not have to change the password on first login.
- The account must be linked to the exact Employee record that was just created.
- Do not create duplicate accounts if an account already exists for that employee.
- Preserve the existing tenant/company isolation.

01012345678

2. Employee Login

Employees must be able to log in using:

Username = their phone number
Password = their current account password

The employee must only be able to access their own data.

Backend authorization must enforce this.
Do not rely only on hiding UI elements.

An employee must never be able to access another employee's:

4. Password Reset / Regeneration

Because passwords must be securely stored as hashes:

Do NOT store the employee's password as plaintext just so administrators can view it later.

Instead provide:

When an authorized Owner/Admin generates a new password:

- Replace the old password.
- The new password becomes the employee's current password immediately.
- Show the newly generated password to the authorized administrator.
- Allow the administrator to copy it.
- Allow the administrator to share it through WhatsApp using the button described below.

The generated password should be strong and random.

The system must never display the old password after it has been replaced.

- The old password is invalidated.
